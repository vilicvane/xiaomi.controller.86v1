# 点击反馈的局部绘图与计时

这套独立版本针对 tap v1 用户报告的间歇连续点击卡顿、漏计和恢复星标问题。
v1 的源码、二进制、测试和61项冻结材料保留原字节；新版本仍使用已审核的
主容器3804b108..3804be70和辅助容器3807a764..3807a920，不扩大借用范围。

静止、完全展开且已经提交整卡时，仅清除底部249..269的21行，重画星标或数字。
初次呈现和滑动覆盖层仍完整合成。原PAN仍提交整帧，局部画布写入的减少
不代表原驱动的旋转/传输也改成局部更新，真实吞吐需实机观察。

feedback_pending继续在184B context的+180，语义明确为：0=已经提交并锚定；
1=新计数等待成功PAN；2=PAN成功但等待有效CLOCK。只对新计数成功提交后的
有效单调时钟启动800ms。失败或排队不清序列，同一计数的动画重绘不续期。

恢复星标前，以及PAN接受星标后清零前，分别短持两publisher锁，确认输入释放、
无正在进行的手势及两订阅队列为空。新增计数绘图的PAN不在这些短锁内执行。
原有owner切换仍在双publisher锁内PAN并提交owner，保留原交接事务。

物理输入原队列只有8条且满后覆盖旧样本，不能凭局部绘图宣称任意速度的点击
均无损。ARM模型的故意溢出示例及真实用户观察必须分开记录。

安装/回退使用独立Set-PanelNativeGitHubTapFast.ps1和三页材料；回退目标为
tap v1，再用tap自己的入口回card，之后逐级返回smooth/ease/drawer/broker/stock。
完整断电仍按用户要求跳过。安装、模型和真实观察以本版本独立结果为准。
