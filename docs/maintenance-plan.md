# 从研究原型进入维护阶段

记录日期：2026-10-07。整理前基线为已安装的 `native-image-drawer`，程序、输入和结果保持
冻结。本次先整理研究记录并阶段性提交，随后开发新的维护版本；以下需求**尚未实现**。

## 用户需求

| 需求 | 整理时状态及边界 |
| --- | --- |
| 取消第三键三击切换 | 只在新维护固件移除。历史三击源码、研究记录、结果及回退版原样保留 |
| 自定义画面双击显示 IP 和端口 | 当前上传图片会隐藏地址，需要新增可发现的地址入口；不将上滑误判为双击 |
| 浏览器访问 `IP:port` 到前端页面 | 当前端口只有 raw TCP；新增浏览器 HTTP 入口，用于上传及 API 文档 |
| 锁屏后自动打开自定义界面 | 用户确认语义：原界面息屏后切回 custom，保留息屏状态，唤醒后看到 custom |

顶边下拉/上滑仍承担原界面往返，原米家应用、系统调度及网络服务继续复用。取消三击
不等于拦截原 MCU 的物理按键动作；保留此前样本与历史行为的完整记录。

## 待实现的设计方向

以下是 agent 的维护方案，属于待实施设计，不描述当前协议或硬件验证结果：

- 端口 18086 改为 HTTP，不为研究原型添加 raw TCP 兼容分支。`POST /api/image` 接收
  固定 VIMG header + RGB565 的 307216B body，复用已验证的图像校验与 GUI 发布边界。
- `GET /` 在配置了前端 URL 时用 HTTP 303 跳转；URL 尚未确定，未配置时提供本机说明页。
  前端域名与 Cloudflare 部署属于后续工作，不在本次整理中编造实际地址。
- HTTP API 需要实现浏览器 CORS 和必要的 OPTIONS 路径。云端 HTTPS 页面访问局域网的
  浏览器权限/网络条件须单独实测，不把“设备返回 CORS header”当作端到端已经可用。
- 双击在完整轻触序列上识别，切换图片/地址展示时不丢弃已上传 RAM 图像；手势、虚拟
  输入、展示状态及新上传的交互需要独立模型和用户验收。
- 息屏触发应观察已确认的系统生命周期状态，在安全 GUI 边界切回 custom，不强行点亮
  屏幕。不把某次背光寄存器值直接等同于锁屏语义，也不重初始化原字体/GUI 状态。

主容器当前只余 16B，辅助容器余 20B。移除自有三击检测预计能释放空间，但 HTTP、双击
与息屏入口能否在既有容器完成尚未确认；必须先编译及审查，不能先承诺新布局。
新版本使用独立材料，直接回退目标为精确 image drawer，不覆盖已有 freeze 或扩大未经
确认的代码/Flash 范围。

## 完成标准

阶段一整理的完成标准是文档区分当前和历史、入口可找到、证据和回退边界可追踪，并
保持所有冻结材料原字节；它不更改设备。阶段性提交后再实现功能。

维护版需要独立离线模型、writer mock 与 review，再记录完整页读回、暖启动、HTTP
请求/上传、双击地址、手势、息屏/唤醒及原米家运行的各自结果。此前完整断电测试的
用户跳过决定仍有效，不重复要求；不能将旧版本结果写成新维护版已经通过。
