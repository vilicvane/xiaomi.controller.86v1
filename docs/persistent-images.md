# 图片持久保存

上传成功后，面板保存原始 PNG、JPEG 或 VIMG 文件，启动时自动解码并显示最近一张有效图片。
没有保存图片时，仍显示地址画面。双击查看地址、上下滑切换和自动返回的操作不变。

网页通过图片能力接口的 `persistent: true` 识别支持持久保存的固件，再以本次上传的
HTTP 202 确认成功，按钮显示“画面已保存”。响应 body 为空，保存承诺来自这两个条件；
旧固件只显示“画面已接收”，重启后仍需重新发送。

## 怎样保存

图片保存在 MMC 的两个专用文件 `/data/86v1-image.0` 和 `/data/86v1-image.1` 中，
与 `/data/86v1-return.0`、`.1` 的自动返回设置分开，也不改动原厂的 Wi-Fi 或身份文件。
每份记录包含版本标记、序号、文件长度及校验，然后是原始图片，最大文件内容 1MiB。
保留两份需要最多约 2MiB 空间；解码后的 RGB565 画面仍在 RAM 中供显示使用。

保存前会检查两个文件及其 FAT 对象，向另一个槽写入新图片，再同步、关闭并重新打开，
逐字节比较完整记录。全部成功后才更新运行状态并排队显示。
启动时按序号尝试加载；较新的记录校验失败或无法解码时，尝试上一份。
下一次保存保护实际成功加载的记录，避免损坏的新记录导致有效旧图被覆盖。

## 失败及备份

空间不足、I/O 或确认失败返回 503，当前画面不被本次请求替换；存储路径出现无法确认属于
本项目的文件时返回 409，程序不会擅自覆盖。若中断只留下不足四字节的标记，也会按无法确认
归属处理，需要检查文件，而非自动删除重试。

保存成功后，显示发布或网络响应仍可能失败。没有收到 202 时，新图片可能已经保存，
因此客户端不能自动重发，也不能承诺旧的持久图片一定未改变。

双槽减少覆盖唯一有效记录的风险，但不等于 FAT 文件系统与 MMC 在任意掉电时都安全。
离线测试模拟了写入中断、损坏、短读写和资源失败；真实掉电恢复尚未验收。
当前验证范围见 [发布结果](../firmware/releases/maintained-persistent-images-20261008-a.json)。

本轮实机验证了三种格式保存、拒绝损坏图片，以及不执行系统关机钩子的两次暖重启：
直接上传的 JPEG 和正式网页上传的 PNG 均由设备自动加载，完整 RGB565 像素读回一致。
完整断电测试按用户要求跳过，不将暖重启结果作为掉电耐久性证明。

完整 NOR 备份和固件恢复**不包含或删除**这些 MMC 文件。保存原始上传图片作为自己的备份；
恢复旧固件后它不会加载这些图片，但文件仍然存在，重新安装支持版本可再次加载。
当前没有远程删除或清空图片接口。
